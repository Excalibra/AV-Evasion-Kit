# AV Evasion Kit

It integrates techniques including Indirect Syscalls, ETW patching, Module Stomping, string encryption and IPv4 obfuscation to circumvent detection by mainstream antivirus software and endpoint detection and response (EDR) systems.

## Core Features

### Shellcode Processing
- ✅ **Shellcode Patching:** Replacement of equivalent instructions to disrupt static signature matching.  
- ✅ **XOR Encryption:** Custom key producing encrypted data indistinguishable from random data.  
- ✅ **IPv4 Address Obfuscation:** Shellcode disguised as an array of IPv4 addresses, free of endianness issues.

### Loader Evasion Techniques
- ✅ **Indirect Syscall:** Jumps to `syscall;ret` instructions within ntdll to bypass user-mode hooks.  
- ✅ **Halo’s Gate:** Resolves hooked Nt* functions by deriving System Service Numbers (SSNs) from neighbouring stubs.  
- ✅ **ETW Patching:** Blinds EDR event collection via Indirect Syscall.  
- ✅ **.text Code Cave:** Utilises padding within the module’s own .text section to store syscall stubs, requiring no additional executable memory.  
- ✅ **Module Stomping:** Overwrites the .text section of a legitimately signed Microsoft DLL for execution.  
- ✅ **Compile-time String Encryption:** All sensitive strings are XOR-encrypted and decrypted onto the stack at runtime.  
- ✅ **HeapAlloc Decryption Buffer:** Employs heap allocation rather than VirtualAlloc.  
- ✅ **Direct Function-Pointer Invocation:** No CreateFiber or callback APIs.  
- ✅ **Zero Anti-Sandbox / Zero System Fingerprinting:** No queries for CPU, memory, virtual-machine processes, etc.  
- ✅ **Manual IPv4 Parsing:** Avoids sscanf to minimise CRT imports.  
- ✅ **Stub Self-Cleaning:** Restores original .text padding content after execution.  
- ✅ **SecureZeroMemory:** Immediate erasure of plaintext data from heap and stack.  
- ✅ **Single-File Deployment:** No helper.dll required; a single executable suffices.  
- ✅ **Silent Windowless Operation:** Compiled with `-mwindows` as a GUI application.

## Technical Architecture

### 1. Shellcode Processing Pipeline

```
Original Shellcode
      │
      ▼
┌─────────────────┐
│ shellcode-patch │  Equivalent-instruction substitution (disrupts byte signatures)
└────────┬────────┘
         ▼
┌─────────────────┐
│shellcode-encrypt│ XOR encryption (custom key)
└────────┬────────┘
         ▼
┌─────────────────────┐
│shellcode-obfuscate- │ IPv4 address obfuscation
│ ipv4                │
└────────┬────────────┘
         ▼
   IPv4 array (C format)
         │
         ▼
┌─────────────────────┐
│ gen_embed_data.py   │ Generates payload_data.h (XOR-encrypted)
└────────┬────────────┘
         ▼
   #include "payload_data.h"  ← compiled into loader.c
```

### 2. Loader Execution Flow

```
Program start (main)
      │
      ▼
  PatchETW() ← Indirect Syscall patches EtwEventWrite
      │
      ▼
  Decrypt embedded key onto stack ← DecryptStr(enc_key)
      │
      ▼
  HeapAlloc + IPv4 de-obfuscation ← decrypt and parse from enc_ipv4[]
      │
      ▼
  XOR decryption restores shellcode
      │
      ▼
  SecureZeroMemory(key) ← erase plaintext key from stack
      │
      ▼
  LoadLibrary("msimg32.dll") ← load legitimately signed DLL
      │ (fallback: dcomp.dll → dwmapi.dll)
      ▼
  Parse PE to locate .text section
      │
      ▼
  Indirect Syscall writes to .text ← BuildSyscallStub → NtWriteVirtualMemory
      │ (fallback: WriteProcessMemory)
      ▼
  FlushInstructionCache
      │
      ▼
  SecureZeroMemory + HeapFree ← erase plaintext from heap
      │
      ▼
  CleanupSyscallStubs() ← restore original .text padding
      │
      ▼
  Function-pointer call (.text) ← direct execution
```

### 3. Key Characteristics

| Dimension                  | Implementation                                      |
| -------------------------- | --------------------------------------------------- |
| Source of executable memory | .text section of signed DLL (Module Stomping)      |
| Code-writing method        | Indirect Syscall / WriteProcessMemory               |
| Syscall stub storage       | .text Code Cave (zero additional executable memory) |
| Decryption buffer           | HeapAlloc (heap allocation)                         |
| Execution method           | Direct function-pointer invocation                  |
| String protection          | Compile-time XOR encryption, runtime stack decryption |
| System-information queries | None                                                |
| IPv4 parsing               | Manual (zero CRT imports)                           |
| Stack-trace appearance     | msimg32.dll!.text (legitimate module)               |
| Imported DLLs              | KERNEL32 + msvcrt only                              |
| Memory sanitisation        | SecureZeroMemory + HeapFree                         |
| Deployment model           | Single file (no helper.dll)                         |

### 4. DLL Fallback Chain

```
msimg32.dll → dcomp.dll → dwmapi.dll
```

## Quick Start

### Environment Requirements
- Operating system: Windows 10/11 (x64)
- Python: 3.8+
- Compiler: GCC (MinGW-w64)
- Shellcode: 64-bit raw shellcode

### One-Click Shellcode Processing

```bash
# Place your shellcode in the scripts directory
cp your_shellcode.bin scripts/shellcode_raw.bin
cd scripts/

# Step 1: Patch shellcode
python shellcode-patch.py shellcode_raw.bin

# Step 2: XOR encryption
python shellcode-encrypt.py shellcode_patched.bin "your_key"

# Step 3: IPv4 obfuscation
python shellcode-obfuscate-ipv4.py shellcode_encrypted.bin

# Step 4: Generate encrypted data header
python gen_embed_data.py

# Step 5: Compile loader
gcc -mwindows -o loader.exe loader.c -s
```

## Usage Guide

### Single-File Deployment (loader.c)

This version adopts an embedded-data architecture. All payload data is compiled into the loader; no additional DLL is required.

1. Run `gen_embed_data.py` to produce `payload_data.h`.  
2. `payload_data.h` contains the encrypted IPv4 array and key.  
3. `loader.c` includes the data via `#include "payload_data.h"`.  
4. Compile; no further files are needed.

**Advantages:**
- Single-file deployment; no helper.dll.  
- Fewer LoadLibraryA calls, reducing NtQuerySystemInformation triggers.  
- All sensitive data encrypted at compile time; no plaintext present in the binary.

## Script Descriptions

### shellcode-patch.py
Utility for modifying shellcode byte signatures. Scans for known equivalent-instruction patterns and performs substitutions that preserve instruction length and semantics.

```bash
python shellcode-patch.py <shellcode_file>
```

Output: `shellcode_patched.bin`

### shellcode-encrypt.py
XOR encryption utility for shellcode.

```bash
python shellcode-encrypt.py <shellcode_file> <key>
```

| Parameter        | Description                                      |
| ---------------- | ------------------------------------------------ |
| `shellcode_file` | Shellcode file to be encrypted                   |
| `key`            | Encryption key (arbitrary non-empty string)      |

Output: `shellcode_encrypted.bin` + `shellcode_encrypted.c`

### shellcode-obfuscate-ipv4.py
IPv4 address obfuscation utility.

```bash
python shellcode-obfuscate-ipv4.py <shellcode_file>
```

Output: `shellcode_obfuscated_ipv4.c`

### gen_embed_data.py
Embedded-data generation script. Extracts the IPv4 array and key from `shellcode_obfuscated_ipv4.c` (or payload_dll.c) and produces a compile-time XOR-encrypted C header.

```bash
python gen_embed_data.py
```

Output: `payload_data.h`

## Troubleshooting

### Issue 1: Decrypted payload fails to execute
**Diagnostic steps:**
1. Compare the first 50 bytes of the decrypted output with the original shellcode.  
2. Verify that the key extracted by gen_embed_data.py matches the key used during encryption.  
3. Confirm that the IPv4 array is complete (no truncation).

### Issue 2: Shellcode architecture mismatch
**Cause:** Loader compilation architecture differs from shellcode architecture.  
**Resolution:**
- 64-bit shellcode → default GCC (64-bit).  
- 32-bit shellcode → requires 32-bit GCC environment (MinGW32).

### Issue 3: No observable behaviour in virtual machines
**Cause:** This version contains no anti-sandbox exit logic and is designed to execute in any environment.  
**Verification:** Test on a physical Windows machine.

### Issue 4: Stomped DLL crashes
**Cause:** The .text section of `msimg32.dll` is smaller than the shellcode.  
**Resolution:** The loader contains built-in fallback logic that automatically attempts `dcomp.dll` → `dwmapi.dll`.

### Issue 5: Compilation error – payload_data.h not found
**Cause:** gen_embed_data.py has not been executed.  
**Resolution:** Run `python gen_embed_data.py` before compiling.
